Guardrails

Rules an agent must follow however it is asked, with optional checks on what it writes.

What a guardrail is

A guardrail is a rule in plain words that is given to the agent as a hard rule above every request, skill and tool result. It can also carry patterns: whatever the agent writes is checked against them before anyone sees it, in workflow results, saved chats and customer replies.

Built-in guardrails

GuardrailWhat it does
No financial informationCustomers never get company financial data. Prices written in the company knowledge may be quoted, nothing else.
No personal data of customers or staffNever reveal who else bought, wrote or works here, and never ask for card or ID numbers.
Stay on topicOnly talk about the company, its products and how to reach the team.
No promises or professional adviceNo guarantees, no legal, medical or financial advice.
Mask personal detailsReplaces real names and numbers with stand-ins before they reach the model (read more).
Older SQL ServerTells the agent how to query SQL Server 2008 and 2008 R2.

Where a guardrail applies

  • All agents: every agent follows it, unless you take it off one agent in Settings > Agents.
  • Chosen agents: add it with the Guardrails tag box on an agent card.
  • Customer channels: every WhatsApp and Instagram reply follows it, whichever agent writes the reply.

Write your own

  1. Press Add guardrail.
  2. Write the rule in plain words, for example Never mention competitors by name. If asked about them, say you can only talk about our own products.
  3. Optionally add patterns: a word or a regular expression, not case sensitive, for example (revenue|profit|salary). A match blocks the whole reply (the fallback text is sent instead) or redacts just that part.
  4. There is a special check that blocks a reply naming an amount of money that is not written in the company knowledge.
  5. Choose where it applies, then save. Use the test box to try it before relying on it.
